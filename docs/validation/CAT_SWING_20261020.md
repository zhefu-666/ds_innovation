显式命令为：

```sh
python3 tools/runtime/record_baseline.py BINARY \
  --compare tests/fixtures/runtime_legacy_baseline.json \
  --platform-baseline tests/fixtures/runtime_legacy_aarch64.json
```

CMake 仅在 `CMAKE_SYSTEM_PROCESSOR=aarch64` 时明确追加该补充参数。比较器验证实际 `platform.machine()`；在 x86 误用 ARM 补充会返回 2。其他 7 项用例字段和资源摘要继续精确比较。原夹具、比较器默认行为及历史 37/38 失败记录没有改写。

## 存储与构建异常

首次在 `/home/cat/refactor-validation/20261020-r4-swing` 构建，`config_loader.cpp` 编译发生 GCC 13 内部错误（segmentation fault）；同源同参数以较低并行度复编后该对象成功，但 `runtime.cpp` 随后也发生内部错误。两次均未完成本批主程序构建，未以这些产物声明完整回归通过。

只读内核日志发现 `mmcblk0p2` 实际 EXT4 故障，包括 checksum invalid、`Delayed block allocation failed ... error 117`、`Data will be lost`，system journal 也有损坏信息。错误与构建及前批相机短跑时间重叠。已停止在该根分区持续构建或记录，将原日志回收到本机；没有执行 fsck、修改挂载或重启。

`/dev/shm` 实测为可执行 tmpfs，容量约 3.9 GiB。后续隔离目录改为 `/dev/shm/r4-swing-validation-20261020`，源码从本机重新传入并逐文件校验；JSON 头文件从本机传入，RKNN SDK 头摘要与前批冻结值一致，临时编译文件也写入 tmpfs。该路径重启即失，证据与二进制须回收到本机并核对摘要。

tmpfs 首次全构建在既有 `disperse_turn_stage.cpp` 的 STL 实例化处也发生 GCC 内部崩溃；因此迁移内存文件系统没有消除异常，不能认定构建异常仅由写盘引起。失败日志独立保留，不修改源码、优化参数或 PIC 来绕过；主机长期稳定性仍未验收。

随后发现 tmpfs 中初始 SHA-256 全通过的 `runtime_legacy_baseline.json` 出现两字节非预期变化；期间未运行 CTest 或负向测试，也未写该夹具。本机独立 `cmp -l` 确认 1-based 偏移 `120505` 从 `=` 变成 `5`，`120507` 从空格变成 NUL；变异文件摘要为 `5508472a28c7bc2abe3c38a6cedadceaa7eaaaf780302042693a4f1cfb9a6b6f`，本机原夹具摘要仍为冻结值。原/变异文件、逐字 diff 和初始/后续检查清单均已保全，没有恢复远程坏夹具来重跑验收。

只读检查另确认 `/usr/libexec/gcc/aarch64-linux-gnu/13/cc1plus` 与本机包 `g++-13-aarch64-linux-gnu 13.3.0-6ubuntu2~24.04.1` 的 MD5 记录不符：包记录 `11d4beb250b55cadd78a4b97c7a89f7e`，实际 `81075ce9f9f3981c99814cc81ceebb9e`。连续两次 SHA-256 均为 `42528bf65af333350aaea6d21c775b30f22cf9129a498a176548929f5c25490f`。所查其余相关包未报告差异，但包记录本身也在受影响主机上，尚未用独立可信 `.deb` 核验。未发现可用的 ECC 计数或其他足以确定硬件原因的记录。

因此停止全部远程构建、新批 CTest 和新批相机验收。四次全构建均失败，**本轮没有完整新 ARM 主程序或最终 CTest 结果**。已生成的 67 条阶段集成摘要虽与本机冻结前输出逐字一致，也只算不稳定环境中的观察；新主程序 7 项应用对照、显式 ARM 基线、相机持续/信号/无效设备检查均未完成。主机恢复完整性后必须从本机可信源码重新完整验收，不能复用这些失败构建。

为保全用户远程独有代码，已通过 SSH stdout 直接流式归档全部 30 个 dirty/untracked 文件（295,929 字节）和三份既有部署二进制（3,550,776 字节）到本机 `camera/deployment-backup/`，远程不创建备份文件。33 项文件的远程备份前/后摘要与本机解包摘要全部一致，无排除项；`git status`、完整 diff 与 HEAD 一并保存。备份不改变部署和工作树。

前批任务测试异常对象已核对：仅 `.rela.text` 两条重定位类型的低字节不同，0-based 文件偏移为 `0x6ae78` 与 `0x6af98`；低字节从错误的 `0x11`/`0x40` 恢复为正常 `0x1b`/`0x15`，其余机器码、符号和内容相同。这确定了损坏形态，但缺少中间汇编和原始落盘校验，不能把编译器、汇编器、内存、存储或拷贝中的任何环节认定为直接根因。此次存储故障仍需独立处理。
