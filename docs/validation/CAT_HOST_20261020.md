## 构建与回归

```sh
cd /home/cat/refactor-validation/20261020-r4-turn/source
cmake -S . -B ../build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DRESCUE_ENABLE_TELEMETRY=ON -DRESCUE_ENABLE_RKNN=ON \
  -DRESCUE_RKNN_INCLUDE_DIR=/home/cat/ds_innovation/benchmark_results \
  -DCMAKE_PREFIX_PATH=/home/cat/refactor-validation/20261020-r4-turn/deps
cmake --build ../build -j4
ctest --test-dir ../build --output-on-failure --output-junit ../evidence/ctest.xml --timeout 60 -j2
```

完整目标最终构建通过。CTest **37/38 通过，1 失败，0 跳过**，耗时 8.73 秒。任务、六批阶段及顶层集成、配置、几何、导航、遥测、比赛 socket、机械规则和伪串口测试均通过。过去本地沙箱不能绑定 socket 的 `rescue_match_tests` 在本主机通过。

唯一失败为 `rescue_runtime_legacy_baseline` 的 geometry stdout 逐字比较。7 个固定用例中其他 6 个完全一致，全部返回码、stderr 及 23 个既有资源摘要均匹配。唯一文本差异：

```text
冻结 x86 基线：frame=1 zone_valid=1 points=6 residual_m=7.81572e-08 reason=ok subzone=supply
当前 ARM64：  frame=1 zone_valid=1 points=6 residual_m=7.72043e-08 reason=ok subzone=supply
```

差值为 `9.529e-10 m`。其他帧、有效点数、判定原因及 `frames=3 accepted=2 hardware_output=disabled` 摘要一致。持久夹具保持原样，SHA-256 仍为 `c828d652eb7316c817ab6182ba13f8202496b59f9b66b06dd9abdbd108b4d79f`；没有放宽比较或把失败记为通过。

为核对差异来源，从原始提交独立导出源码，在 `legacy-source/` 和 `legacy-build/` 构建原版 ARM64 主程序，使用同一套 7 项用例与当前 ARM64 程序比较。参数、返回码、完整 stdout/stderr **7/7 逐字一致**；原版第一帧残差也为 `7.72043e-08 m`，因此该跨环境数值差异在原版已存在。本次对照仍不等于完整现场流程等价证明。

原版通过 Git archive 导出，归档 SHA-256 为 `6978e27460aa22c6ec62f874310ec5ac855054137f4b88b8f055d58c917b4118`。使用同主机工具链、Release、遥测 ON，仅构建主程序；SDK 头路径通过隔离源码内符号链接提供，不修改原始源码。

首次全目标链接另发现 `push_task_tests.cpp.o` 的两处重定位类型与机器指令不匹配，其中一处类型未定义。保留异常对象后，以相同源码和参数重编译，再独立复编一次；两次正常对象逐字相同，SHA-256 为 `5758adc975ceff09672ed4ae566b4341ddb885e8a4c0eee63471fd53b7a004ed`，链接及任务测试通过。异常对象与正常对象只差两个字节；异常 SHA-256 为 `1476b90e738380ecd8a1c97148be6fe656611cbf790ee591ff21de76a0f9d865`。本次没有修改源码、优化级别或 PIC 设置，异常未复现，具体成因未确定。

```sh

  --detect-image IMAGE --dry-run --no-show --team blue \
  --model /home/cat/ds_innovation/models/detect_fp.rknn \
```
