# 帧率问题定位与修复（2026-10-17）

远程：cat@192.168.1.121:/home/cat/ds_innovation。

## 原因

1. 历史23–24fps使用混合检测+INT8 pose（pose约22–26ms），现方案是混合检测+FP16 pose（约49ms）。模型组合不同，历史24fps不能直接当作当前同精度方案的基线。单FP16 pose context每帧约49ms，完整同帧双模型的持续吞吐理论上已受约20fps限制。
2. 新增采集、pose、预览工作线程后，默认允许CPU0–7混合调度，OpenCV默认8线程。R1的CPU0–3为A55、CPU4–7为A76。未约束CPU调度和OpenCV线程池导致可复现的额外开销。不是NPU未启用或频率不足：诊断时NPU保持1GHz，未改任何系统频率、调速器或服务。
3. 此前16.8fps是关闭网页发布的基准，15.3fps是开启发布与桥接的结果，两者不是同条件回退比较。将发布上限从10提高到30也增加了处理负载。
