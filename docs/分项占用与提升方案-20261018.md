# 当前版本分项占用与最优提升路线（2026-10-18）

结论：限制FPS的是约36–38ms的pose NPU执行；消耗CPU最多的是每秒60次MJPEG解码。当前最合理路线是保留已验证的分核并行与原生FP16输入，先减少无效解码及图像拷贝，再以有界流水线压缩NPU空档；若要求稳定超过30FPS，重点必须转向pose模型执行优化和精度验收。继续调分核、删除绘图/日志不会带来数量级提升。

## 最优提升路线与验收方式

1. 保留现有检测core0 / pose core1并行，不继续以换核为主要方向。前一轮六种单核组合23.09–23.80FPS，两核pose24.05FPS，相邻对照23.68/23.59FPS，短测小差异不值得直接改正式配置。NPU已1GHz，没有已证实的升频余量。
2. 第一项工程改动应解决“60次解码只消费约24帧”。保持USB采集60FPS，用有界的最新压缩帧槽持续排空V4L2，消费端只解码将供给同帧双模型的最新帧；保留新鲜度和超时保护。这能避免解码后才丢掉约一半帧，降低CPU/内存争用，主要收益是CPU与时延稳定性，不能承诺显著提升FPS。原JPEG解码器及预处理保留，先做同一压缩帧输入像素一致性和9图输出对照，再验证frame_age、实际拍摄时延、断流失败关闭。不要用简单停止grab导致内核缓冲堆积。
3. 硬件MJPEG解码作为下一条CPU优化候选，而非已就绪方案。板端存在/dev/mpp_service、/dev/rga、MPP/RGA库和ffmpeg mjpeg_rkmpp，实际离线测试却出现45秒超时；另做10秒有日志复测，详见decoder-summary.json和bounded_mjpeg_rkmpp.log。因此不能直接部署。若修通，需对比同一真实相机JPEG的软件/硬件解码像素，关注YUV矩阵、full/limited range、RGB顺序和resize插值；不同像素必须重新验模型输出和精度。消除软件解码的理论CPU节省上限约56个百分点，真实硬解仍有提交、同步和颜色转换成本。
4. 保留模型与精度的FPS改进采用有界双缓冲：常驻工作线程，下一帧预处理与上一帧NPU并行，预览独立所有权并减少多余clone；每一帧检测与pose绑定同一frame_id，最多保留一个待处理最新帧，禁止积压或混帧。以逐帧同输入输出一致、P95/P99延迟和丢帧新鲜度验收。当前约36.24ms pose NPU形成理想上限约27.6FPS（1000/36.24，忽略其它成本），这只是理想上限，不是实施收益承诺。预处理总计仅约1.48ms，因此单纯RGA替换预处理/重写线程池不会突破30FPS。
5. 若目标是稳定30FPS以上，必须实质缩短pose NPU服务时间到33.3ms以下并给其它阶段留预算，例如针对真实输入的模型图/算子分析、选择性混合量化、重新导出编译。先定位高耗时层与敏感输出，再用覆盖有效安全区、远近距离、遮挡和光照的真实图验证关键点误差、有效区召回、误判及非有限输出；对照FP16与当前版本。现有纯INT8异常模型不可复用；本轮没有重训或改模型，不承诺精度不变。此前9图逐位一致测试不能替代改量化后的场景精度验收。

执行顺序建议：最新压缩帧按需解码及所有权梳理 → 同帧有界流水线 → pose专项优化。MPP硬解先在独立程序解决超时，再决定是否替换按需软件解码。无需优先重写NMS、JSON、绘图或日志，也不建议以降分辨率、跳过pose换取“同精度提升”。

## 文件与限制

summary.json保留六组对照；profile*.csv保留全部分项；*-system.json保留每秒温度、NPU频率、进程RSS、线程/proc采样和串口描述符。短命std::async线程可能在1秒采样间隙消失，因此以阶段CLOCK_THREAD_CPUTIME_ID和进程resource CPU为主，不将/proc线程快照当作完整线程CPU账本。

run_remote.py可复测；decoder_probe.py为首轮硬解试验，45秒超时；decoder_bounded.py保留软件/硬件各10秒超时边界的补测日志。硬解失败不会改动正式程序。原始120张MJPEG相机码流保留远端source.mjpeg，软件解码9张RGB文件只在远端保留，未将体积大的原始媒体复制到本地。

补测结果：同一120帧码流，ffmpeg软件mjpeg解码退出0，墙钟0.919秒、累计CPU1.110秒；mjpeg_rkmpp在10秒上限内未完成，已终止，日志停在stream mapping。输入实际为Baseline JPEG yuvj422p、full range；是否与此格式相关尚未定位。离线裸MJPEG显示的25fps为解析器时间基准，原采集为60FPS，不能据此宣称相机降到25FPS。未获得硬解输出，尚未进行软硬件像素比较。

最终核查：无业务主进程、无ffmpeg进程，/dev/video0无占用，match-main.service仍disabled。业务源码、模型、正式二进制及启动配置未修改。
