# RKNN角点飞线修复与接入说明

本说明对应实际验证的文件 SHA256 `d0249684fed94195f56e4ce273acb6f9997aaae04f6af3c7d8bbb6e7db2458ea`，源文件为 `../pose_A_rawxy_export_fix_20261105T055254Z/A_rawxy_INT8_EXPERIMENTAL.rknn`。使用既有修复产物，本轮没有重训、重新量化或增加导出候选。它仍是实验模型，原始定位、旧参考回退与独立验收问题未因此清除。

## 为什么这样修复

旧版把原始角点乘2、加锚点、乘步长的运算放在RKNN图中。实际NPU旧版的角点输出已经严重偏离浮点参考；框、分类、可见性与手动反量化检查不能解释该大幅偏移。新版保留INT8网络输出原始角点，将这段坐标计算交给CPU。新旧同图实际NPU对照证据见 `actual_comparison.json`。这是对异常计算路径的绕开；尚未完成编译器内部逐算子根因定位，不能将某个具体算子定为唯一原因。

## 输入与五路输出

输入 RGB uint8 NHWC `[1,640,640,3]`；缩放保持比例、padding=114，模型内部除255。不要在外部再归一化后以uint8接口传入。每帧记录实际gain/pad；原图坐标在最后恢复。

|索引|实际查询名|形状|实际板端dtype|
|---|---|---|---|
|0|boxes|1,4,8400|INT8|
|1|scores|1,2,8400|INT8|
|2|base_xy_raw|1,8,8400|INT8|
|3|far_xy_raw|1,8,8400|INT8|
|4|visibility|1,4,8400|INT8|

类别仍为左/右两个实例，每个实例4个语义点；五路是五个张量，不是五种角点。左右中央端点保持独立可见性，不强制重合。

## C/C++处理顺序

1. `rknn_query`核对五路名字、形状、dtype。查询实际文件，禁止硬套旧四路大小。
2. `rknn_outputs_get`为每一路设置`index`和`want_float=1`，保证浮点缓冲区一直有效，直到解码完成再release。该模式下不要再次反量化。若选择原生INT8输出，必须逐路使用各自`(int8_value-zp)*scale`。
3. 采用 `rawxy_to_26.hpp` 中的 `pose_rawxy_to_26`，将五路浮点缓冲区转成旧双分支的26通道布局：4框、2分类、8原角点、8远景角点、4可见性。此函数只进行坐标计算和重排。
4. 角点按80×80/40×40/20×20的行优先顺序，对应步长8/16/32：`x640=(2*raw_x+grid_x)*stride`，`y640=(2*raw_y+grid_y)*stride`。raw_x/raw_y不是像素，直接画它会错误。
5. 原检测/NMS之后按冻结的框面积路由混合两组角点。见包内 `host_decode.py`；`far_max=0.04392929565847024`，`near_min=0.14768375983277818`，缺失或重复实例退回原分支。不可在这一步调整阈值来掩盖错误。
6. 按`(xy640-pad)/gain`还原原图；可见性≥0.5才画对应点，两端都可见才画边。记录未经显示裁剪的异常，不能用裁剪证明正确。
7. 如需平滑，再调用冻结的 `smoother.py` 与 `filter_config.json`。保持raw和filtered分别输出。此次视频平滑在电脑端完成，模型推理在真实NPU完成，不能由此声称板端主程序已集成平滑。

最小调用示意（缓冲区来自本帧五路`want_float=1`）：

```cpp
std::array<const float*,5> buffers;
std::array<std::size_t,5> elements{33600,16800,67200,67200,33600};
for (int j=0;j<5;++j) buffers[j]=static_cast<const float*>(outputs[j].buf);
auto merged26=pose_rawxy_to_26(buffers,elements);
// 再进入已有双分支26通道的NMS、面积路由和原图恢复流程。
```

C++适配器已在当前电脑上用六组真实NPU输出验证：每组218400个合并浮点元素与Python实现完全一致，见 `cpp_adapter_verification.json`。该测试不等于板端主程序已接入；此次没有把适配器安装到板端，也没有修改板端源码、二进制、配置或生产模型。

## 实测边界

板端只加载明确哈希的实验文件离线推理，未启动主程序、相机、串口或车辆。新增文件只在独立 `/tmp/pose_rknn_export_resolution_20261105T062910Z/`，包括实验模型、输入和证据数据；测试程序通过SSH标准输入临时执行。每次探针内部生产配置、主程序和默认模型的前后哈希一致；跨阶段配置和默认模型一致，但主程序二进制曾发生变化，来源本轮无法确认。探针没有使用该主程序，直接加载的RKNN Runtime库首尾哈希一致。详见cross_stage_runtime_change.json。

新版不能直接替换旧四路文件。后续主程序接入必须同时适配五路接口，并重新进行实时相机、时延、板端平滑与车辆场景验收。

## 尚未解决的远景实例歧义

805帧精确输入实测中，远景432帧有76帧在固定NMS之后出现3/4个检测（同图SDK模拟仅4帧歧义），路由依原规则退回原分支。没有为减少歧义调整阈值或覆盖规则。粗粒度框量化与NPU/SDK数值差异可能参与，根因尚待验证。因此本模型仍不可视为合格候选。视频按冻结规则每类显示最高分；全部检测与歧义另存，不能以画面两条区域判断实例数正常。详见remaining_instance_ambiguity.json。
