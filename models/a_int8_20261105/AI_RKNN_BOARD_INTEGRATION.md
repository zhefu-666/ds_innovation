## 5. 必须接对的输入

- 原始图像通常是 BGR uint8，先等比缩放、补边到 640×640，填充值 114。
- 然后转换为 RGB，按 `[1,640,640,3]` 的 uint8 NHWC 送入模型。
- RKNN 转换配置内部是 mean=0、std=255；外部不要再次除以 255。
- 不拉伸图像，不把 BGR 直接当 RGB；每帧保留原图宽高和实际 gain、pad。
- 1280×720 原图应得到 gain=0.5、pad=(0,140)。其他尺寸按参考函数计算，并核验奇数补边和坐标恢复。

若实际 runtime 报出的属性不同，先记录属性并核对输入绑定方式，不靠强制 reshape 或重复归一化让程序勉强运行。

## 6. 四路输出和解码规则

### 输出约定

以下是解码器要求的规范形状。先查询板端输出属性，按名字、索引、布局和类型映射；不得只看元素总数。

| 路 | 名称 | 形状 | 含义 |
|---:|---|---|---|
| 0 | boxes | `[1,4,8400]` | 640 输入坐标系的 cx、cy、w、h |
| 1 | scores | `[1,2,8400]` | 两类别概率，已经 sigmoid，无独立 objectness |
| 2 | xy_experts | `[1,16,8400]` | 前8通道原分支四点XY，后8通道远景分支四点XY |
| 3 | old_visibility | `[1,4,8400]` | 四点可见性概率，已经 sigmoid |

两组 XY 内部均按 `p0x,p0y,p1x,p1y,p2x,p2y,p3x,p3y` 排列。

- class 0：左区，四点 LA、LB、LC、LD。
- class 1：右区，四点 RC、RD、RE、RF。
- 不把两组 XY 当成八个最终物理点，也不强制左右 C/D 相同。

### 逐路反量化

必须给解码器正确的浮点值：

- 若 C API 支持请求浮点输出，可使用其输出结构的 `want_float=1`；先核对实际 API/版本，不能把此字段当成 Python Toolkit 的通用 inference 参数。
- 若返回原始整数，按**每路实际元数据**分别计算 `(q-zero_point)*scale`。不能共用一套 scale/zp，也不能复制旧模型参数。
- 已反量化的浮点输出不再重复转换。`host_decode.py` 的 float32 类型转换不是反量化函数。

### 后处理顺序

1. 每个位置取最大类别概率；检测阈值严格 `score>0.5`，分类别 NMS IoU=0.45，最多300个检测。
2. 框从 cxcywh 转为 xyxy，再还原原图并裁到边界。
3. NMS 后每类恰好各1个时，取两个框中最大的原图面积占比 area，计算远景权重；缺类或多实例则 w=0，记录歧义/缺失并退回原分支。

```text
far_max = 0.04392929565847024
near_min = 0.14768375983277818
w = clip((near_min - area) / (near_min - far_max), 0, 1)
XY = base_XY × (1 - w) + far_XY × w
```

4. 可见性取原分支；XY 按 `(x-pad_x)/gain`、`(y-pad_y)/gain` 回到原图并检查边界。
5. 每实例保留四个 `[x,y,visibility]`。点显示阈值 `visibility>=0.5`；画边为 `(0,2)、(1,3)、(0,1)、(2,3)`，仅两个端点均当前有效时画线。

不要额外 sigmoid、额外乘 objectness、颜色吸附、强制矩形、重排点序，或重新把像素坐标与概率合并量化。此前概率归零就是坐标和概率共用约3.35的量化步长造成的。

## 7. 平滑接在哪里

处理链必须是：

```text
原图 → letterbox/RGB → RKNN → 逐路反量化 → NMS
→ 双分支XY路由 → 还原原图坐标 → 平滑 → 有效性判定/显示
```

平滑器接收原图坐标，在内部转换到640坐标系计算，返回的仍是原图坐标；画线前不要再次还原坐标。

当前参数直接读取 `runtime_config.json` 的 `filter`：

```json
{
  "coordinate_space": "640 square letterbox pixels",
  "min_cutoff_hz": 1.2,
  "max_cutoff_hz": 8.0,
  "beta_hz_per_pixel_per_second": 0.016,
  "derivative_cutoff_hz": 1.0,
  "max_gap_seconds": 0.2,
  "class_box_reset_iou": 0.2,
  "visibility": 0.5,
  "detection": 0.5
}
```

按 `(类别, 点编号)` 分开维护状态，每个视频流一个实例，不能每帧新建实例。核心算法：

```text
raw_velocity = (current_640 - previous_raw_640) / dt
velocity = 对raw_velocity做1Hz低通
cutoff = min(8.0, 1.2 + 0.016 × norm(velocity))
alpha = 1 - exp(-2π × cutoff × dt)
filtered = previous_filtered + alpha × (current - previous_filtered)
```

时间戳使用真实采集的单调秒值。回放固定视频可用 frame_index/fps，不使用处理结束时间代替采集时间。

必须保持以下行为：

- 点不可见或检测缺失：清除对应历史，不用旧点补线。
- 新点首次出现：用当前原始测量初始化。
- 时间不递增、间隔>0.2秒、类内框IoU<0.2：重置对应历史。
- 同类多实例：显示规则按最高分取原始测量并重置；业务端应另外标记歧义，不能声称身份关联已解决。
- 越界点：重置历史，消费端检查坐标和 audit，不因保留了原始值就判为有效。
- 换视频、跳帧回放、相机重连、尺寸变化：主动 reset。

不增加历史点存活、不增加预测补点、不叠加原工程另一层平滑后仍称是本版效果。`gated` 目前只是原始副本，没有异常剔除；`predicted_only=false`。若改参数或增加其他滤波，必须另列实验并重新评价，不能混入本次接入结果。

## 8. 实施方式

### 若现有程序是 Python

复用现有运行时加载方式，实现一个“返回四路已反量化浮点数组”的适配函数，接入核心逻辑为：

```python
# self.filter在流初始化时创建；plan从runtime_config.json加载。
rgb_u8, gain, pad = letterbox(frame_bgr)
outputs = infer_dequantized_outputs(rgb_u8)  # 由实际板端API实现
raw_all, route = decode(outputs, gain, pad, frame_bgr.shape, plan["router"])
result = self.filter.update(raw_all, capture_time_s, gain, pad, frame_bgr.shape)
# 保存raw_all、route、result["raw_selected"]、result["filtered"]、result["audit"]。
# filtered已是原图坐标，不能重复反变换。
```

这是接口示意，不是已验证的完整板端 API 示例；不要原样虚构不存在的 `infer_dequantized_outputs` 实现。

### 若现有程序是 C/C++

在原语言中实现与参考文件一致的行为，特别核对：输入内存布局与生命周期、输出逐路 dtype/量化参数、box格式、两组XY的通道次序、分类别NMS、路由面积分母、clip和pad/gain、平滑速度单位、alpha公式、重置和可见性。

优先加独立后处理模块与单独实验配置，保留旧实现用于对照，不通过大范围重构来接入一个模型。

## 10. 怎样判断本次接入完成

分别给出三个结论，不混写：

1. **程序接入完成**：准确哈希文件在板端实际加载，输入输出和解码正确，raw/filtered都能输出且有实际视频。
2. **板端一致性与资源验证**：同图与SDK参考的差异、实际耗时/内存/丢帧、状态重置和异常处理有完整证据。跨次导出疑点是否解决单列说明。
3. **模型业务验收**：原有每槽mean≤3、P95≤6输入像素、可评片段漏点/不可见误报、旧参考与边线不退步等要求继续保留；业务阈值/独立场景缺失时不能自行宣布通过。

原SDK图上的参考均值为：近景INT8原始10.71→平滑10.13、远景6.91→6.28输入像素。近景仍漏4个人工可见点，并有2个不可见点误报。数值是历史参考，不是板端应当强制拟合到的答案，也不是已达标效果。
