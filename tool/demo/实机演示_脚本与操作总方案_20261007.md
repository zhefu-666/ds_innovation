# 实机演示：脚本与操作总方案

版本：2026-10-07。适用：RK3588 / LubanCat，0°开框、20°关框的新机械候选。

**这是一套独立的演示入口，不会调用旧的高速启动脚本。识别、寻找、单趟搬运各有自己的入口。当前配置仍有真实验收缺项：可以准备和检查脚本，不等于已经允许底盘运动。**

## 1. 先选你想做的事

所有命令均在远程演示源码目录执行：

```bash
ssh -o HostKeyAlias=192.168.161.7 cat@192.168.34.7
cd /home/cat/ds_innovation_candidates/demo-20261007/source
```

未加 `--run` 的动作脚本默认只检查文件、验收条件和命令，**不打开设备**。`search.sh --preview` 是例外：它显式打开相机、IMU和MCU只读反馈，仍不发送控制字节。`status.sh` 和 `stop.sh` 按名称直接查询/停止本套演示。

| 我想要的效果 | 直接使用的命令 | 会发生什么 | 何时结束 |
|---|---|---|---|
| 查看哪些演示还缺条件 | `tools/demo/preflight.sh` | 检查配置与本地文件，不发指令 | 打印清单后退出 |
| 仅识别画面中的物块 | `tools/demo/recognize.sh --run --seconds 60` | 相机+检测模型+遥测；**不打开MCU或IMU串口** | 60秒或Ctrl+C |
| 看“选哪个物块”，但不转车 | `tools/demo/search.sh --preview --seconds 60` | 读相机/IMU/相机反馈，输出像素排序和几何有效性；无TX | 60秒或Ctrl+C |

| 找到、框住、搬运、放下，一趟结束 | `tools/demo/carry_once.sh --run --site-clear --seconds 60` | 完整执行一趟，不直接假定框内已有物块，不自动跑第二趟 | 投放证据成立；否则故障/时限退出 |

| 关框 | `tools/demo/frame_close.sh --run --site-clear` | 零速度，发送20°，新动作编号，等待配置指定的A6状态 | 反馈匹配或2秒超时 |

| 相机回到前方测距档 | `tools/demo/camera.sh --offset-deg 5 --run --site-clear` | 相机TX偏移5° / RX读回45°，保持夹爪状态和编号 | 到位/超时 |
| 相机观察20°档 | `tools/demo/camera.sh --offset-deg 20 --run --site-clear` | TX20° / RX60°；只作观察，不能据此声明测距已标定 | 到位/超时 |
| 相机观察40°档 | `tools/demo/camera.sh --offset-deg 40 --run --site-clear` | TX40° / RX80°；只作观察，不能跨档复用旧ROI | 到位/超时 |
| 小幅前进 | `tools/demo/move_forward.sh --run --site-clear --speed 0.05 --seconds 0.5` | 前进0.05m/s，保持机构；指令积分约0.025m，**非实测位移** | 0.5秒后补零速 |
| 小幅后退 | `tools/demo/move_backward.sh --run --site-clear --speed 0.05 --seconds 0.5` | 后退0.05m/s，后方须清空，保持机构 | 0.5秒后补零速 |
| 小幅左转 | `tools/demo/turn_left.sh --run --site-clear --wz 0.20 --seconds 0.5` | 正角速度0.20rad/s；名义约5.7°，**非实测转角** | 0.5秒后补零速 |
| 小幅右转 | `tools/demo/turn_right.sh --run --site-clear --wz 0.20 --seconds 0.5` | 负角速度0.20rad/s，保持机构 | 0.5秒后补零速 |
| 看搬运状态机的无硬件回放 | `tools/demo/replay.sh --run` | 使用合成/已记录观察输入，不开相机、NPU或串口 | 回放结束 |
| 查看本套脚本正在做什么 | `tools/demo/status.sh` | 显示本套演示的进程、动作与控制socket | 立即返回 |
| 停止本套演示 | `tools/demo/stop.sh` | 向本套控制器请求STOP，再终止对应演示进程；不会pkill其他项目 | 等待最多5秒确认进程退出 |

`--site-clear` 的含义是：现场人员确认本轮机构/前后/旋转扫掠空间已清空；寻找和搬运还确认场内只有己方区域、没有人员或对手进入。它不是传感器测出来的安全结论。脚本仍保留视觉通道、反馈、新鲜度、时限和故障门槛。

底盘点动最多1秒，速度最多0.10m/s、角速度最多0.25rad/s。拒绝负时长、NaN以及越限参数。结束、异常和Ctrl+C都尝试发送零速，并保持最后机构角度/编号；断连时是否真正停止必须依赖已实测的下位机看门狗和现场急停。

默认文件：`config/demo_20261007.json`。

- 新机械配置：`config/frame_20261007.pending.json`。
- 演示验收记录：`config/demo_acceptance.pending.json`。

准备自己的现场配置（这些复制命令不会启动车辆）：

```bash
cp config/demo_20261007.json config/demo.local.json
cp config/frame_20261007.pending.json config/frame.demo.json
cp config/demo_acceptance.pending.json config/demo_acceptance.local.json
```

编辑 `demo.local.json`，将 `frame_config` 指向 `config/frame.demo.json`，将 `acceptance` 指向 `config/demo_acceptance.local.json`。其他路径按现场实际情况填写。然后：

```bash
export RESCUE_DEMO_PROFILE="$PWD/config/demo.local.json"
tools/demo/preflight.sh
```

以后表格内的脚本均会读此环境变量，不必反复加路径。也可单次指定 `--profile config/demo.local.json`。新开SSH终端要重新export。

机械配置沿用OpenCV文件格式，验收字段使用数字 `0/1`；演示验收文件使用JSON布尔值 `false/true`。A6状态必须填实际观测到的不同0/1，不能因为命令为20°就直接写成反馈1。

验收文件至少记录：`operator`、`verified_date`、`evidence_record`。前进/寻找/搬运要求 `watchdog_verified=true`，且 `watchdog_max_ms` 是实际测量所得、不超过200ms。静止开闭不要求先做底盘测试；底盘点动不要求已经通过自身测试，避免验收顺序循环。寻找需要 `manual_wheel_test_passed`，搬运另需 `multi_view_dataset_passed`。

只寻找模式不会要求尚未涉及的框内多档/捕获停车配置，但仍校验机械坐标、动作映射、车体开闭扫掠包络和地面几何，并由独立输出限制器禁止前进、关框和切相机。搬运保持完整门槛。

## 4. 第一次上机：先做静止映射取证

如果0°/20°与A6状态还没有实测，不要运行普通开关脚本。先在实物上禁用车轮运动输出，并确保框体周围无人、机构无干涉，再逐次运行：

```bash
# 只检查命令，无设备访问
tools/demo/commission_open.sh
tools/demo/commission_close.sh

# 每条命令单独执行，观察实物，再决定下一条
tools/demo/commission_open.sh --run --site-clear --wheels-disabled
tools/demo/commission_close.sh --run --site-clear --wheels-disabled
```

这两个入口分别下发原始角度0°/20°，速度始终为0，从新鲜A6获取当前编号和相机角度，新编号1..255循环，同一次事务重发编号不变。最多2秒，不反向动作，不自动写入验收配置。

输出 `ID_ECHO_ONLY` **只表示编号回传**。记录：0°实物是不是开、20°实物是不是关、各自的A6原始状态、动作耗时、是否干涉。开和关各10次，逐次记录。任何一次方向不符或卡住就结束本轮，不要交换“开/关”名称掩盖实物差异。

按实际记录填写新机械配置的动作映射和演示验收文件，再用普通开关脚本复核。坐标与扫掠空间、地面标定、多档框内多边形分别验收，不随动作映射一起自动放行。

## 6. 三个决策演示分别怎么摆、怎么看

### A. 识别演示：只看目标，不控制机构

1. 固定车体，让相机能看到绿、黑、橙、蓝物块，逐个放入，再同时放入；不要用悬空手持遮挡结果冒充地面检测成功。
2. 启动网页后，运行：

```bash
tools/demo/recognize.sh --run --seconds 60
```

3. 看检测框、类别、置信度。当前模型颜色约定是：绿→普通物资、黑→核心物资、橙→伤员、蓝→禁止物。以模型类别文件/界面实际输出复核，不能只凭框颜色认类别。
4. 本脚本不开MCU/IMU，不做几何接近、不开关框。界面运动许可关闭是正确结果。
5. 结束时记录漏检、误检、遮挡情况。识别到不等于允许搬运。

### B. 寻找演示：看候选，再演示找到即停

先准备相机内部5°档。不能在识别或寻找程序占用串口时再运行相机脚本；先停止当前演示，再设角度。

```bash
tools/demo/camera.sh --offset-deg 5 --run --site-clear
tools/demo/search.sh --preview --seconds 30
```

只读阶段：放两块绿色物资，改变画面占比，观察 `[DEMO_SEARCH_PREVIEW]` 中ID、锁定状态、`pixel_mode`、占比和几何有效性。首趟只允许绿色物资；更大的蓝/黑目标不应抢占首趟合法目标。改变相机档位或画面尺寸后，比较历史清空，重新确认。

正式原地寻找前，把物块摆在框外且不在己方区内；只留己方区域，清空整个车体（含打开机构）的旋转扫掠空间。运行：

```bash
tools/demo/search.sh --run --site-clear --seconds 20
```

验收关注点：

- 车体只原地转，`vx=0`，不会直接冲向物块。
- 框的开/关角度和相机档位保持启动时状态；若需要变更，先退出、单独执行相应脚本。
- 目标通过像素锁定与决策确认后输出 `demo_target_found`，停车退出；不能进入APPROACH/RUSH。
- 无合法目标、几何失效或通道不安全时不得冒险；到时退出，返回非0表示未完成目标寻找，不能计为成功。
- 重复运行每次都是新演示，不能把一次锁定保存在下一次中冒充新观察。

### C. 搬运演示：完整一趟，不跳过确认

摆放：先演示一块绿色普通物资；目标在框外、己方区域外，己方物资区可见且空位足够，前后与转弯空间已清空。起点与目标距离要在本轮0.30m捕获前累计前进预算内，投放后退出要满足0.20m后退预算；不因现场距离过大而放宽脚本限制。

```bash
tools/demo/carry_once.sh                 # 先看缺项；不打开设备
tools/demo/carry_once.sh --run --site-clear --seconds 60
```

流程：寻找/确认目标 → 对齐接近 → 停车开框 → 低速进入 → 停车关框 → 多相机档位观察 → 允许搬运后前往己方投放位置 → 停车开框 → 确认反馈后退出 → 核对投放证据 → 停车结束。

限制：

- 这是“完成一趟完整搬运”的入口，**不是**“我说框内有一块就直接开始CARRY”的捷径。
- 最大线速度0.10m/s；进入速度和搬运速度可能更低；时限最多60秒。无起步定时前冲。
- 框内多档证据必须一致、类别数量符合物料规则；不确定不能搬运。
- 开框反馈未确认，不能后退；投放未确认，不能增加成功计数。
- 输出 `demo_delivery_complete` 且 `delivered_total=1` 才是本次软件判定完成。`demo_delivery_unconfirmed`、SAFE_STOP或时限退出均记为未完成。
- 成功后不会再转身找下一块。每次新启动都重置任务，因此首趟规则重新要求普通物资；此入口不能直接用核心物资/伤员代替首单。

若只想提前检查流程逻辑而无实机条件：

```bash
tools/demo/replay.sh --run
```

回放输入含合成/记录观察，不能作为实际抓取、保持、释放或停车证据。

## 7. 推荐演示次序

| 阶段 | 操作 | 预期展示 | 继续条件 |
|---|---|---|---|
| 开始前 | preflight + status；核对急停、设备占用和场地 | 缺项清单明确，无其他演示占用 | 所做项目的前提齐全 |
| 第1段 | recognize 30～60秒 | 四类目标识别和遮挡/未知边界 | 画面新鲜、类别符合 |
| 第2段 | 单独open、close、camera 5° | 机构动作及反馈对应 | 已验收映射有效，无干涉 |
| 第3段 | 前/后各0.5秒、左/右各0.5秒，分次执行 | 点动结束停车、机构保持 | 零速与实物停车一致，后方清空 |
| 第4段 | search --preview，随后search --run 20秒 | 合法目标按占比选择、原地寻找、找到即停 | 不前进、不隐式开关框 |
| 第5段 | carry_once --run 60秒 | 完整一趟 | 多档和释放证据齐全，未触碰限制 |
| 收尾 | stop、status，退出web | 演示进程退出，实物停车 | 保存本轮日志与现场视频 |

首次映射/标定/看门狗测试是准备工作，不要临到展示现场才省略。出现误检、无法确认、超时属于需要记录的结果，不为追求演示连贯而改为自动放行。

## 8. 如何停、如何排错

另一个板卡终端：

```bash
cd /home/cat/ds_innovation_candidates/demo-20261007/source
tools/demo/stop.sh
tools/demo/status.sh
```

- `stop.sh`校验进程PID及启动时刻，避免PID复用后误杀其他程序；它只管理本套脚本启动的演示。
- 对旧运行入口 `/tmp/rescue-match.sock`，如确实需要停止旧主程序，使用旧控制入口：`python3 /home/cat/ds_innovation/tools/match/match_ctl.py stop --socket /tmp/rescue-match.sock`。本套脚本不会擅自给旧项目发控制指令。
- 软件STOP回执、零速度包和进程退出都不是独立的实物停车证明；现场急停始终可用。SSH断开后不得假设远程停止已经送达。

| 提示 | 原因 | 处理 |
|---|---|---|
| `BLOCKED` / 验收字段缺失 | 当前记录尚未通过 | 先完成对应现场记录，不能跳过 |
| `Mechanical calibration pending` | 原生校验器拒绝未验收机械数据 | 查提示字段对应的坐标、映射、扫掠或多档标定 |
| `startup_pitch_not_rest_or_5deg` | 相机既不在开机静止位RX40（旧0°）也不在旧5°（RX45） | 退出演示，运行camera 0或5°并确认反馈，再启动；启动后程序自行转到旧5°搜索 |
| `pitch_not_calibrated` / `ground_mapping_unavailable` | 当前档位无有效地面标定 | 补该档标定；不能直接启用机械推导模型代替 |
| `round_invalidated` / `multi_view_unconfirmed` | 静止位姿、闭合状态或多档对应关系不足 | 停车检查视野/遮挡/标定。近景看不到可靠位姿时会被拒绝 |
| `Resource temporarily unavailable` / 串口被占用 | 已有演示或旧工具持有锁 | 正常停止原占用者，不拔线或强杀未知进程 |
| 只有网页，没有新画面 | 主程序未启动或已退出 | 查看对应演示终端与日志 |
| 模型/库/二进制不存在 | 资源根目录或构建路径不对 | 修改demo.local.json；不自动下载或替换模型 |
| 退出码2 | 被门槛拒绝、超时或演示未完成 | 查看具体原因，不能计为成功 |
| 退出码130 | Ctrl+C或stop发来的终止信号 | 核对进程和实物停止 |
